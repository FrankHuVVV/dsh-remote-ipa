# ADR-0001 · 原生渲染，不用 WebView

- **日期**：2026-10-25
- **状态**：已采纳

## 背景

DSH 的对话内容来自服务器，包含 Markdown、代码块、GFM 表格，以及 `dsh-ui` 围栏里的
结构化 JSON。鸿蒙版的既有决定（`harmony-reference/.../ADR-0001-arkui-native-over-webview.md`）
是「不用 WebView」：聊天与 HTML 预览全部原生渲染。

## 决定

iOS 版沿用同一条边界：**聊天、Markdown、表格、代码块、文件预览全部用 Flutter 原生组件渲染**，
不引入 `webview_flutter`，不把消息正文拼成 HTML。

## 后果

- ✅ 不可信的会话内容与文件拿不到 JS 引擎，也没有导航能力；外链必须用户点击才交给系统浏览器。
- ✅ 渲染路径可单测（块级解析 + 行内解析都是纯 Dart）。
- ⚠️ Markdown 覆盖面受限于自研 `MarkdownLite`：目前不支持嵌套引用、脚注、HTML 内联。
  遇到时退化为普通文本，**不丢内容**。
- ⚠️ `dsh-ui` 的 22 种卡片需要逐个用 Flutter 重画（P5），成本明显高于「塞进 WebView」。

## 替代方案与为什么不选

| 方案 | 为什么不行 |
|---|---|
| `webview_flutter` + 现成 Markdown 渲染 | 消息内容来自服务器，等于把执行权交给不可信输入；且离线不可测 |
| 服务端渲染成图片 | 丢选择/复制能力，体积与延迟都变差 |
| 只做纯文本 | 代码块与表格是日常内容，退化不可接受 |
