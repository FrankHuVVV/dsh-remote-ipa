# 安全

## 资产与边界

| 资产 | 在哪 | 保护方式 |
|---|---|---|
| 设备令牌（Bearer） | iOS 钥匙串 `dsh_hosts_v1` | 系统加密；普通偏好里只有常量句柄；不写日志 |
| `DSH1:` 配置文本 | 用户剪贴板 / 聊天记录 | 不加密（它本身就是凭据载体），只提示「发给自己」 |
| 服务器文件内容 | 只在内存里渲染 | 按不可信文本处理：不执行、不解析 HTML、外链需点击 |
| 会话历史 / 图片 | 内存 | 不落盘、不备份 |

## 威胁模型（按可能性排序）

1. **配置文本外泄**：用户把 `DSH1:` 发到群里。文本里有设备令牌，拿到即可读写该设备的授权范围。
   处置：在电脑上吊销该设备令牌并重新配对。客户端无法「撤回」已发出的文本。
2. **局域网中间人**：明文 HTTP 下同网段可嗅探。建议在可信网络使用，或给中继配 https。
   `NSAllowsLocalNetworking` 只放行本地网段，不会把公网也降级。
3. **侧载应用被替换**：自签名 IPA 的完整性只由签名证书保证；证书若来自不可信来源，
   安装的就不是这份代码。只从自己的 GitHub Actions artifact 取包，并核对 SHA-256。
4. **手机丢失**：钥匙串条目是 `first_unlock_this_device`，不进 iCloud；
   丢失后应在电脑上吊销设备令牌（比远程擦除更直接）。
5. **服务端被攻破**：客户端能做的只有「不放大」—— 不缓存明文、不自动执行服务端返回的链接。

## 明确的取舍

- **不做证书固定（pinning）**：服务端常是家用 IP + 自签证书，pinning 只会把用户挡在门外。
- **不做「记住密码」以外的凭据管理**：只存设备令牌，不存 Apple ID / DSH 账号密码。
- **不在客户端做权限判断的最终裁决**：`scopes` 只用于**隐藏入口**，
  真正的授权边界在服务端；被改过的客户端最多看到 403。
- **不接第三方崩溃 / 统计 SDK**：那等于把令牌所在进程的内存快照交给第三方。

## 代码里必须保持的几件事

1. `DshClient` 是唯一网络出口；`ui/` 里出现 URL 拼接即违规。
2. 令牌只在 `_authHeaders()` 里出现，且 `toString()` 不打印 header。
3. `DSH1:` 解码永不抛异常（粘贴环境不可控）；编码才抛（生成端人在电脑旁）。
4. 文件 / 消息内容一律走 `SelectableText` / 原生 Markdown，不拼 HTML、不 `eval`。
5. 日志里不出现令牌、路径全量、消息正文（当前没有生产日志，只有 `flutter` 默认输出）。
